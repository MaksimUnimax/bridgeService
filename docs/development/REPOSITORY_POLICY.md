# Политика репозитория

## Роль репозитория

`MaksimUnimax/bridgeService` — единый источник правды для Business Bridge 2 Direct Connection.

Здесь ведутся:

- серверный код;
- код Chrome-расширения;
- установщик и обновление;
- полное ТЗ;
- roadmap;
- архитектурные решения;
- статусы всех ранов;
- журнал выполненных изменений;
- тестовые доказательства;
- релизная документация.

## Ветки

### `main`

Продовая ветка. В ней должны находиться только принятые версии кода и документации, пригодные для пользователя.

### `development`

Рабочая ветка проекта. Все раны `BB2-DIRECT-00` — `BB2-DIRECT-18` сначала отражаются здесь.

Перед продовым релизом изменения переносятся в `main` контролируемым squash merge или чистым релизным commit.

## Как отражается ход работы

После каждого рана обновляются:

1. `docs/development/RUN_STATUS.md` — состояние всех ранов.
2. `docs/development/WORKLOG.md` — фактически выполненная работа.
3. Документация и ADR, затронутые раном.
4. Test evidence и SHA-256 изменённых артефактов.
5. Код, относящийся только к текущему рану.

Ран не считается завершённым, пока его статус и доказательства не записаны в репозиторий.

## Очистка перед продовым релизом

Перед выпуском:

- в `main` остаются пользовательская документация, исходный код, установщик, тесты и release notes;
- временные журналы разработки могут быть исключены из релизной ветки;
- ветка `development` может быть удалена после принятия релиза;
- история `main` должна оставаться понятной и чистой.

Важно: репозиторий публичный. Удаление файла или ветки не гарантирует полного исчезновения данных из Git-истории, forks, caches и внешних копий. Поэтому секретная или персональная информация не публикуется даже временно.

## Запрещено публиковать

- пароли;
- API-токены;
- cookies;
- приватные ключи;
- pairing codes;
- содержимое секретных файлов;
- полные пользовательские prompts и отчёты с чувствительными данными;
- `.env` с реальными значениями;
- дампы production-базы;
- реальные SSH credentials.

Для секретов допускается только имя и состояние `PRESENT/ABSENT`.

## Неприкосновенность действующего Bridge

До полной приёмки Direct Connection запрещено изменять рабочую систему:

- `/opt/business-bridge-2`;
- `business-bridge-2.service`;
- `127.0.0.1:18083`;
- рабочую SQLite DB;
- рабочие токены, state и logs.

Новая версия устанавливается и тестируется только в изолированных ресурсах.
